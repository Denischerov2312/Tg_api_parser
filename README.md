# Tg_api_parser

Собирает анонсы IT-соревнований (хакатоны, олимпиады, конкурсы, CTF, кейс-чемпионаты, game jam) из публичных Telegram-каналов в `events.csv`. Посты разбирает нейросеть DeepSeek.

## Установка (Windows)

```
cd %USERPROFILE%\Desktop\Tg_api_parser
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env` и вставьте `API_ID` и `API_HASH` с https://my.telegram.org, а также `DEEPSEEK_API_KEY` (ключ ProxyAPI).
2. Впишите каналы в `channels.txt`.

## Запуск

```
python parser.py
```

При первом запуске Telethon спросит номер телефона и код из Telegram. После этого появится файл `session.session`. Это доступ к вашему аккаунту, никому его не передавайте.

## Как это работает

1. Берёт сообщения за последние `DAYS_BACK` дней, при следующих запусках только новые (запоминает в `state.json`).
2. Предфильтр без нейросети: отбрасывает посты короче `MIN_TEXT_LEN` символов, посты без слов вроде «хакатон», «олимпиада», «конкурс», «CTF», «чемпионат» (`COMPETITION_RE` в `parser.py`), одинаковые тексты из разных каналов и посты, которые уже есть в базе.
3. Оставшиеся посты отправляет в нейросеть (`LLM_MODEL`). Она решает, анонс ли это соревнования, и извлекает название, даты, дедлайн регистрации, формат, город, приз, ссылку.
4. Отбрасывает прошедшие события и склеивает дубли с уже известными:
   - **A** — тот же пост (по ссылке на пост) в нейросеть повторно не отправляется;
   - **B** — совпадает ссылка на регистрацию (без параметров; голые домены и ссылки на Telegram не учитываются);
   - **C** — совпадает дата начала и названия похожи не меньше чем на `TITLE_SIMILARITY` (0.85).
   Дубль не теряется: его пост добавляется в колонку `sources` основного события, пустые поля дозаполняются.
5. Все события хранятся в `events.json`. `events.csv` пересобирается каждый запуск и содержит только актуальные события (разделитель `;`, открывается в Excel).

Если API нейросети недоступен (нет денег на балансе, нет сети), запуск прерывается и `state.json` не обновляется, поэтому при следующем запуске посты обработаются заново.

Чтобы заново просканировать каналы (например, после изменения `DAYS_BACK`), удалите `state.json`. Уже известные посты повторно в нейросеть не пойдут.

## Поиск дублей нейросетью (вручную)

```
python dedup_llm.py --dry-run   # показать, что модель предлагает склеить
python dedup_llm.py             # склеить
```

Отправляет модели список актуальных событий и просит найти записи об одном соревновании, которые не поймали правила B и C (разные названия, анонс и напоминание, отбор и финал). Перед изменением `events.json` сохраняется копия `events.json.bak`.

## Статистика и логи

Папка `logs/`:

- `parser_runs.csv` — строка на каждый запуск `parser.py`: модель, сколько постов прочитано, отсеяно предфильтром (`dropped_short`, `dropped_no_keywords`, `dropped_same_text`, `dup_post_link`), отправлено в нейросеть (`sent_to_llm`), ошибок модели (`llm_failed`, `llm_error_pct` — доля постов, по которым так и не пришёл корректный JSON; `llm_bad_json` — все невалидные ответы, включая исправленные повтором), токены, не соревнований (`not_competition`), прошедших (`past`), дублей по правилам (`dup_url`, `dup_title`), новых событий.
- `dedup_runs.csv` — строка на каждый запуск `dedup_llm.py`: модель, сколько событий проверено, групп найдено, некорректных групп (`llm_error_pct` — их доля), склеено записей, токены.
- `parser.log`, `dedup.log` — подробности по каждому посту и решению модели.

Колонка `model` позволяет сравнивать модели: поменяйте `LLM_MODEL` в `.env` и сравните строки статистики.
