# Tg_api_parser

Собирает анонсы **IT-соревнований** из публичных Telegram-каналов: хакатоны, олимпиады, конкурсы, CTF, кейс-чемпионаты, game jam, датафоны. В общем, всё, где человек или команда решает задачи. Посты разбирает нейросеть (по умолчанию DeepSeek V4.1 Flash), результат — таблица `events.csv`, которая открывается в Excel.

```
Telegram-каналы ──► предфильтр (бесплатно) ──► нейросеть ──► отбор + склейка дублей ──► events.csv
  channels.txt      короткие, без ключевых      соревнование?    прошедшие события,        + events.json
                    слов, уже в базе            даты, ссылка...  одинаковые анонсы         + логи
```

## Что понадобится

- **Windows / Linux / macOS** с Python 3.10+ (в проекте зафиксирован 3.14, если пользуетесь `uv`).
- **Аккаунт Telegram**: парсер читает каналы от вашего имени, как обычный клиент.
- **Ключ API нейросети**: по умолчанию [ProxyAPI](https://proxyapi.ru) с моделью DeepSeek. Подойдёт любой OpenAI-совместимый API (OpenRouter, официальный DeepSeek и т.п.), см. [смену модели](#как-сменить-модель-и-сравнить-модели).

## Установка

Скачайте проект:

```
git clone https://github.com/Denischerov2312/Tg_api_parser.git
cd Tg_api_parser
```

**Вариант 1: через [uv](https://docs.astral.sh/uv/) (рекомендуется).** uv сам поставит нужный Python и библиотеки:

```
uv sync
```

Дальше все команды запускаются через `uv run`, например `uv run python parser.py`.

**Вариант 2: через обычный pip:**

```
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS
pip install -r requirements.txt
```

Дальше все команды запускаются как `python parser.py` (не забудьте активировать окружение в новом терминале).

## Настройка

### 1. Ключи Telegram API

1. Зайдите на https://my.telegram.org и войдите по номеру телефона.
2. Откройте **API development tools**.
3. Создайте приложение (название и описание любые, платформа — Desktop).
4. Скопируйте **App api_id** и **App api_hash**.

### 2. Ключ нейросети

1. Зарегистрируйтесь на https://proxyapi.ru и пополните баланс (расход — копейки, см. [статистику](#логи-и-статистика)).
2. В личном кабинете создайте API-ключ.

### 3. Файл .env

Скопируйте `.env.example` в `.env` и впишите значения:

```
API_ID=12345678
API_HASH=0123456789abcdef0123456789abcdef
DEEPSEEK_API_KEY=sk-...
```

Остальные настройки можно не трогать, их описание в разделе [Все настройки .env](#все-настройки-env).

### 4. Список каналов: channels.txt

По одному каналу на строку, в любом формате:

```
@hackathonsrus
codenrock
https://t.me/ctfnews
# строки, начинающиеся с #, игнорируются
```

Подходят только **публичные каналы**. Боты (`@..._bot`) и приватные каналы прочитать не получится.

## Первый запуск

```
uv run python parser.py
```

При первом запуске Telethon спросит в терминале:

1. **номер телефона** в международном формате (`+79991234567`);
2. **код**, который придёт в Telegram (в чат «Telegram», не по SMS);
3. **пароль облачного пароля**, если включена двухэтапная проверка.

После этого в папке появится `session.session`, и больше вход спрашиваться не будет.

Первый запуск читает посты за последние `DAYS_BACK` дней (по умолчанию 30) и может занять пару минут.

## Обычное использование

| Что сделать | Команда |
|---|---|
| Собрать новые соревнования | `uv run python parser.py` |
| Посмотреть сводку по запускам | `uv run python stats.py` |
| Посмотреть, какие дубли найдёт нейросеть (ничего не меняя) | `uv run python dedup_llm.py --dry-run` |
| Склеить дубли нейросетью | `uv run python dedup_llm.py` |
| Открыть результат | открыть `events.csv` двойным щелчком (Excel) |

Каждый следующий запуск `parser.py` читает **только новые посты**: последний прочитанный пост каждого канала запоминается в `state.json`. Поэтому парсер можно запускать хоть каждый час, и за уже обработанные посты платить повторно не придётся.

## Результат: events.csv

Таблица **актуальных** соревнований (прошедшие не показываются), отсортированная по дате начала. Разделитель `;`, кодировка UTF-8 с BOM — открывается в Excel двойным щелчком без «кракозябр».

| Колонка | Что в ней |
|---|---|
| № | Номер события в базе (`events.json`) |
| Начало / Конец | Даты проведения (`ГГГГ-ММ-ДД`), пусто, если в посте не указано |
| Регистрация до | Дедлайн регистрации |
| Тип | `hackathon`, `olympiad`, `contest`, `ctf`, `case` (кейс-чемпионат), `gamejam`, `other` |
| Название | Короткое название соревнования |
| Что делать | Одно предложение о задаче участников |
| Формат | `online`, `offline`, `hybrid`, `unknown` |
| Город | Город проведения (для офлайна) |
| Участие | `solo`, `team`, `any`, `unknown` |
| Для кого | Школьники, студенты, все и т.п. |
| Призы | Призовой фонд или призы |
| Ссылка на регистрацию | Ссылка из поста |
| Упоминаний | Сколько постов говорят об этом соревновании (после склейки дублей) |
| Посты | Ссылки на все эти посты |

Событие считается актуальным, пока не прошла хотя бы одна его дата (окончание или дедлайн регистрации). События без дат тоже показываются, чтобы не потерять анонс.

`events.csv` **пересобирается при каждом запуске** из `events.json`, поэтому правки, сделанные в нём вручную, пропадут. Если нужно что-то сохранить, сохраните копию под другим именем.

`events.json` — полная база всех найденных событий, включая прошедшие, с датами добавления и источниками.

## Поиск дублей нейросетью

`parser.py` сам склеивает очевидные дубли (см. [Как это работает внутри](#как-это-работает-внутри)). Но один и тот же хакатон бывает описан совсем по-разному: «Финал РуКод» и «Международный чемпионат РуКод», отборочный этап и финал Кубка. Для таких случаев есть отдельный скрипт, который запускается **вручную**:

```
uv run python dedup_llm.py --dry-run     # только показать
uv run python dedup_llm.py               # склеить
```

Скрипт отправляет нейросети список актуальных событий (до 150 ближайших) и просит найти записи об одном соревновании. Пример вывода:

```
[ДУБЛИ (пробно)]         #4 Кубок Федерации 2026 — CTF
                           <- #19 Кубок Федерации 2026 — финал
                         причина: id 4 описывает онлайн-отбор, а id 19 — финал того же кубка.
```

- Разные этапы одного соревнования (отбор и финал) считаются одним событием.
- Основным остаётся событие, найденное раньше всех. Посты остальных переносятся к нему, пустые поля заполняются.
- Перед изменениями сохраняется копия `events.json.bak`. Чтобы откатить склейку, переименуйте её обратно в `events.json`.
- Стоимость: один запрос примерно на 3–4 тысячи токенов при 20 событиях.

Рекомендуется сначала запускать с `--dry-run`, просматривать предложения и только потом склеивать.

## Логи и статистика

Всё лежит в папке `logs/`:

```
logs/
├── parser_runs.csv                       статистика: строка на каждый запуск parser.py
├── dedup_runs.csv                        статистика: строка на каждый запуск dedup_llm.py
└── runs/
    ├── 2026-10-10_12-38-36_parser.log    подробный лог одного запуска парсера
    └── 2026-10-10_12-39-06_dedup.log     подробный лог одного запуска поиска дублей
```

Хранятся последние 100 логов каждого скрипта, более старые удаляются автоматически. Статистика в CSV не удаляется никогда.

### Быстрая сводка: stats.py

```
uv run python stats.py          # последние 10 запусков
uv run python stats.py -n 30    # последние 30 запусков
```

Показывает три таблицы:

1. **Последние запуски parser.py**: сколько прочитано, отправлено в модель, ошибок, отсеяно, дублей, новых событий, токенов.
2. **Сводка по моделям**: если вы пробовали разные модели, здесь их удобно сравнить (процент ошибок, доля постов, признанных соревнованиями, токенов на пост, стоимость).
3. **Последние запуски dedup_llm.py.**

Прерванные запуски помечаются как `ПРЕРВАН`, под таблицей выводится причина.

### Подробный лог запуска

Каждый запуск пишет свой файл `logs/runs/<дата>_<время>_parser.log`. Путь к нему печатается в конце запуска («Подробный лог») и хранится в колонке «Лог запуска» статистики. Открывать удобно в любом редакторе (VS Code, Notepad++, Блокнот).

Внутри по строке на **каждый** пост с меткой, что с ним произошло:

```
--- @hackathonsrus (последний прочитанный id: 1590) ---
12:38:42  [уже в базе]             https://t.me/hackathonsrus/1605
12:38:42  [в модель]               https://t.me/hackathonsrus/1599 | Импульс Т1: возвращаемся с главным ИТ-событием осени…
...
========== 2. РЕШЕНИЯ МОДЕЛИ И ДУБЛИ ==========
12:39:00  [не соревнование]        https://t.me/hackathonsrus/1599 | Это ИТ-конференция с деловой программой и спикерами, без конкурсной части | Импульс Т1…
12:39:00  [уже прошло]             https://t.me/hackathonsrus/1598 | Турнир по кибербезопасности «НеоКВЕСТ» | 2026-10-09
12:39:00  [НОВОЕ]                  #20 Solar CTF 2026 | 2026-10-17 (рег. до 2026-10-15) | https://t.me/ctfnews/1652
```

| Метка | Что значит |
|---|---|
| `[короткий]` | Пост короче `MIN_TEXT_LEN` символов (или картинка без подписи), в модель не отправлялся |
| `[нет ключевых слов]` | В посте нет слов вроде «хакатон», «олимпиада», «конкурс», «CTF»… В модель не отправлялся |
| `[уже в базе]` | Этот пост уже обработан раньше |
| `[повтор текста]` | Такой же текст уже был в другом канале в этом запуске |
| `[в модель]` | Пост прошёл предфильтр и отправлен нейросети |
| `[ошибка модели]` | Модель дважды вернула некорректный ответ, пост пропущен |
| `[не соревнование]` | Модель решила, что это не соревнование; рядом её объяснение |
| `[уже прошло]` | Соревнование, но все его даты уже в прошлом |
| `[не онлайн]` | Отброшено настройкой `ONLY_ONLINE=1` |
| `[дубль: ссылка рег.]` | Склеено с известным событием: та же ссылка на регистрацию |
| `[дубль: название+дата]` | Склеено с известным событием: та же дата и похожее название |
| `[НОВОЕ]` | Новое соревнование добавлено в базу |
| `[ошибка канала]` | Канал не найден, нет доступа или Telegram попросил подождать (FloodWait) |

**Как проверить, что фильтры не теряют нужное.** Просмотрите строки `[не соревнование]` и `[нет ключевых слов]`: если там попалось соревнование, расширьте список слов `COMPETITION_RE` в `parser.py` или напишите, какие посты модель ошибочно отбрасывает.

**Поиск по логам в PowerShell:**

```powershell
# Открыть последний лог парсера
Get-ChildItem logs\runs\*_parser.log | Sort-Object Name | Select-Object -Last 1 | Get-Content -Encoding utf8

# Все новые события за всё время
Select-String -Path logs\runs\*_parser.log -Pattern "\[НОВОЕ\]" -Encoding utf8

# Все решения «не соревнование» (проверить, не ошиблась ли модель)
Select-String -Path logs\runs\*_parser.log -Pattern "\[не соревнование\]" -Encoding utf8
```

`-Encoding utf8` обязателен: без него Windows PowerShell 5.1 покажет кириллицу «кракозябрами».

### Статистика в Excel: parser_runs.csv и dedup_runs.csv

Открываются двойным щелчком. Колонки `parser_runs.csv`:

| Колонка | Что значит |
|---|---|
| Дата запуска, Время, с | Когда и сколько длился запуск |
| Статус, Ошибка | `ok` или `aborted` (прерван) и причина |
| Модель | Какая нейросеть использовалась |
| Каналов, Каналов с ошибкой | Сколько каналов в списке и сколько не удалось прочитать |
| Прочитано постов | Всего новых постов во всех каналах |
| Отсеяно: короткие / нет ключевых слов / повтор текста / уже в базе | Отсеяно предфильтром **до** нейросети (бесплатно) |
| Отправлено в модель | Сколько постов разобрала нейросеть |
| Ошибок модели, Ошибок модели, % | По скольким постам модель так и не дала корректный ответ (после повторной попытки) |
| Запросов к API, Невалидных ответов | Все запросы, включая повторные, и сколько ответов пришлось переспросить |
| Токенов на вход / на выход, Стоимость | Расход; стоимость считается, если заданы `LLM_PRICE_INPUT` и `LLM_PRICE_OUTPUT` |
| Не соревнование, Уже прошли, Не онлайн | Отброшено **после** нейросети |
| Дубли: ссылка на регистрацию / название и дата | Склеено с уже известными событиями |
| Новых событий, Всего в базе, Актуальных | Итог по базе |
| Лог запуска | Путь к подробному логу этого запуска |

В `dedup_runs.csv` те же служебные колонки, а также: «Проверено событий», «Групп от модели», «Некорректных групп» (модель указала несуществующий номер или один номер в двух группах), «Склеено записей», «Пробный запуск» (1 = `--dry-run`).

**Что такое «процент ошибок».** Это **технические** ошибки: модель вернула не JSON или ссылку на несуществующее событие. Верность решений по существу (не пропустила ли модель соревнование) автоматически не измерить. Для этого просматривайте строки `[не соревнование]` в подробных логах.

## Как сменить модель и сравнить модели

Модель задаётся в `.env`:

```
LLM_MODEL=deepseek/deepseek-v4-pro-0813
```

Название модели берите в каталоге своего провайдера. Можно поменять и самого провайдера, если у него OpenAI-совместимый API:

```
LLM_BASE_URL=https://openrouter.ai/api/v1
DEEPSEEK_API_KEY=ключ-этого-провайдера
LLM_MODEL=deepseek/deepseek-v4.1-flash
```

**Как сравнить две модели на одних и тех же постах:**

1. Сделайте копию `events.json` и `state.json`.
2. Удалите `events.json` и `state.json`, поставьте модель A, запустите `parser.py`.
3. Удалите `events.json` и `state.json` ещё раз, поставьте модель B, запустите `parser.py`.
4. Запустите `python stats.py`. В таблице «Сводка по моделям» будут обе модели: процент ошибок, доля соревнований, токены и стоимость. Сами решения сравнивайте по подробным логам.
5. Верните сохранённые копии `events.json` и `state.json`.

Чтобы в статистике считалась стоимость, впишите цены модели за 1 млн токенов из прайса провайдера в `LLM_PRICE_INPUT` и `LLM_PRICE_OUTPUT`.

## Все настройки .env

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `API_ID`, `API_HASH` | — | Ключи Telegram API с my.telegram.org (обязательно) |
| `DAYS_BACK` | `30` | За сколько дней читать посты при **первом** запуске (или после удаления `state.json`) |
| `LIMIT_PER_CHANNEL` | `300` | Максимум постов с одного канала за запуск. Ставьте с запасом: если новых постов больше лимита, самые старые из них пропустятся |
| `ONLY_ONLINE` | `0` | `1` — оставлять только онлайн и гибридные соревнования |
| `MIN_TEXT_LEN` | `150` | Посты короче (в символах) не отправляются в нейросеть |
| `TITLE_SIMILARITY` | `0.85` | Насколько похожими (0…1) должны быть названия событий с одинаковой датой, чтобы склеить их автоматически. Меньше — склеивает смелее, но может склеить разные события |
| `DEEPSEEK_API_KEY` | — | Ключ API нейросети (обязательно) |
| `LLM_BASE_URL` | `https://api.proxyapi.ru/v1` | Адрес OpenAI-совместимого API |
| `LLM_MODEL` | `deepseek/deepseek-v4.1-flash` | Модель |
| `LLM_CONCURRENCY` | `5` | Сколько запросов к нейросети отправлять одновременно. Уменьшите, если провайдер отвечает ошибкой лимита (429) |
| `LLM_PRICE_INPUT`, `LLM_PRICE_OUTPUT` | `0` | Цена за 1 млн токенов, только для колонки «Стоимость» в статистике |

## Как это работает внутри

1. **Чтение каналов.** Telethon читает посты новее последнего прочитанного (`state.json`), при первом запуске — за `DAYS_BACK` дней.
2. **Предфильтр (без нейросети, бесплатно).** Пропускаются:
   - короткие посты и картинки без подписи (`MIN_TEXT_LEN`);
   - посты без слов-маркеров соревнований (`COMPETITION_RE` в `parser.py`; список намеренно широкий);
   - посты, которые уже есть в базе (**правило A**);
   - одинаковые тексты из разных каналов.
3. **Нейросеть.** Каждый оставшийся пост отправляется модели вместе с сегодняшней датой и датой публикации (чтобы правильно определить год). Модель отвечает JSON: соревнование ли это и почему, тип, название, даты, формат, город, приз, ссылка. Если ответ некорректный, запрос повторяется один раз.
4. **Отбор.** Отбрасываются не-соревнования, прошедшие события и (при `ONLY_ONLINE=1`) офлайн.
5. **Склейка дублей** с уже известными событиями:
   - **правило B**: совпадает ссылка на регистрацию (без `?utm=...` и т.п.; голые домены и ссылки на Telegram не учитываются, потому что у одного организатора они одинаковые для разных событий);
   - **правило C**: совпадает дата начала, и названия похожи не меньше чем на `TITLE_SIMILARITY` (из названий убираются год и общие слова вроде «хакатон», «чемпионат»).
   Дубль не теряется: его пост добавляется в «Посты» основного события.
6. **Сохранение.** `events.json`, затем `events.csv`, статистика и в самом конце `state.json`.

**Надёжность.** Если API нейросети недоступен (кончились деньги, нет сети, ошибка провайдера), запуск прерывается **до** сохранения: ничего не записывается, `state.json` не сдвигается. При следующем запуске те же посты обработаются заново и не потеряются. В статистике такой запуск помечается `aborted` с причиной.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Заполните API_ID и API_HASH` / `Заполните DEEPSEEK_API_KEY` | Нет файла `.env` или в нём пустые значения, см. [Настройка](#настройка) |
| `@канал: канал не найден, пропускаю` | Опечатка в `channels.txt`, канал приватный или это бот |
| `FloodWait, ждём N сек` | Telegram ограничил частоту запросов. Парсер подождёт и продолжит, а пропущенный канал прочитает при следующем запуске |
| `Ошибка LLM API, запуск прерван` | Проверьте баланс у провайдера, ключ и `LLM_BASE_URL`. Посты не потеряются |
| `Не удалось записать events.csv: закройте его в Excel` | Закройте таблицу и запустите снова. Данные уже сохранены в `events.json` |
| Нашлось мало соревнований | Посмотрите итог запуска: где отсеялось больше всего. Посты `[уже прошло]` — это нормально. Если много `[нет ключевых слов]`, проверьте их в логе |
| Хочу заново просканировать каналы (например, увеличил `DAYS_BACK`) | Удалите `state.json`. Уже известные посты повторно в нейросеть не пойдут, платить за них не придётся |
| Хочу начать с нуля | Удалите `state.json`, `events.json` и `events.csv` |
| Кракозябры в логе в PowerShell | Добавьте `-Encoding utf8` к `Get-Content` / `Select-String` |
| Повторно спрашивает телефон и код | Удалён или повреждён `session.session`, войдите заново |

## Структура проекта

```
parser.py          основной скрипт: каналы → предфильтр → нейросеть → дубли → events.csv
dedup_llm.py       ручной поиск дублей нейросетью
stats.py           сводка по запускам в терминале
common.py          общий код: настройки модели, хранилище, правила дублей, CSV, логи
channels.txt       список каналов
.env.example       пример настроек (скопировать в .env)

.env               ваши ключи                                    ┐
session.session    вход в ваш Telegram-аккаунт                   │
state.json         последний прочитанный пост по каждому каналу  │ создаются при работе,
events.json        база всех найденных событий                   │ в git не попадают
events.json.bak    копия базы перед склейкой дублей нейросетью   │
events.csv         актуальные события для Excel                  │
logs/              статистика и подробные логи                   ┘
```

## Безопасность

- **`.env`** содержит ключи Telegram и нейросети, **`session.session`** — это вход в ваш Telegram-аккаунт: кто получит этот файл, сможет читать и писать от вашего имени. Никому их не передавайте и не публикуйте.
- Оба файла, а также данные (`state.json`, `events.*`, `logs/`) уже исключены в `.gitignore`.
- Если `session.session` всё же утёк: Telegram → Настройки → Устройства → завершите неизвестный сеанс.
